How the project is built

Digital is the source. Everything else is downstream.

Start in Digital. Export once, read-only. That netlist fans out to formal proof, Nexys A7 Artix-7 bring-up, and KiCad copper — then fab, ISA, assembler, and Tomato OS burn back into the running FPGA.

The goal is implementability: Tomato is meant to be built from readily available discrete components, and that constraint shapes the architectural choices — banking, modular decode, dual-LUT slices. The FPGA is a faithful render of what the discrete machine will be, not a separate design.

These four ideas are the spine — everything else on this site hangs off them.

  1. 01

    Dual-LUT ALU — logic rides arithmetic

    Most ALUs pick one result with a giant output mux. Tomato runs two independent 3-input LUT planes per bit straight into the adder — no mux. The opcode is the truth table, reprogrammed every cycle.

    That yields 524,288 native ALU opcodes on the parametric 8-bit slice — 256 × 256 × 8 opcode space. Examples: SHA-256 Choose, A + (B AND C).

    How the slice works →
  2. 02

    32,768 General Purpose Register File — half a Blackwell SM, on SRAM

    RISC-V gives you 32 registers. Tomato's discrete AS6C62256 SRAMs already expose 15 address bits — disconnecting any of them would waste silicon I'm paying for.

    Register Upgrade — full argument →

    32,768 × 32-bit General Purpose Register File = 1,024× RV32I, and half the 65,536 × 32 physical register file in a single NVIDIA Blackwell streaming multiprocessor.

  3. 03

    130 billion vectors — then formal proof

    The datapath isn't hand-waved. Verilator ran 10 billion vectors on the byte slice and 130 billion on the full 32-bit ALU against a golden model — every mismatch aborts.

    SymbiYosys proved the same path at 1b, 8b, and 32b. Example: SHA-256 Choose — (A ∧ B) ⊕ (¬A ∧ C) — 1 cycle here, 4 on a conventional RISC-V core.

The machine

One cycle. Any Boolean of three variables.

Tomato resolves any function of the family f(a,b,c) + g(a,b,c) + h(cin) in a single clock — fused mask-and-add like A + (B AND C), or cryptographic steps like SHA-256 Choose, native in hardware. Register Upgrade →

By Tyrone Marhguy · Computer Engineering ’28 · Penn · 639 hours and counting.

I set out to build a computer from my own architecture at the transistor level. Tomato is what survived that bet — evolved from a 3,488-MOSFET ALU, now a 32-bit machine with an OS that boots to HDMI.

The pivot that made it possible: a parametric Dual-LUT3 datapath. Two 8:1 mux planes per bit feed the carry-select adder. The opcode doesn't select from fixed outputs — it programs the LUTs. Logic and arithmetic happen in the same breath.

Think computing (A ∧ B) ⊕ (¬A ∧ C) — the SHA-256 Choose function — in a single clock cycle. A conventional RISC-V core needs four. That gap is the whole thesis.

Why it wins

No output mux: LUT feeds the adder. Logic rides arithmetic.

Software loops for fused Boolean math become one native hardware step. The truth table rewires every cycle — coarse-grain FPGA fabric, tuned to the smallest unit that still builds a real CPU.

Core equation

out = adder(mux(An, Bn, Cn), mux(An, Bn, Cn), mux(carry / flags))

Operation family

f(a, b, c) + g(a, b, c) + h(cin)

By design, Tomato resolves any Boolean of the family f(a, b, c) + g(a, b, c) + h(cin) in a single clock cycle. Tomato OS is the demo you can hand someone — menu, quirks table, games on HDMI.

II · The Hardware Compiler

A compiler in hardware

I designed a custom finite-state machine (FSM) to autonomously sweep the opcode space. By evaluating inputs A, B, and C against an expected result, the FSM iterates until a matching configuration is identified. This effectively acts as a hardware-level compiler, mapping arbitrary boolean logic operations directly to a single native opcode.

When deployed to an Artix‑7 FPGA, the FSM swept the space until it locked a native opcode.

III · The Build Philosophy

FPGA now. Discrete 74xx on the bench. Transistors someday.

Tomato runs as a full machine on an Artix‑7 FPGA — TomatoOS, HDMI, the Dual-LUT datapath — while the same architecture is built out in discrete 74xx copper, board by board. Lot 07_alu is the first slice leaving the screen. Manufacturability and time set that pace.

Someday, I will lay them out as raw transistors, just as I always intended. Even in this form, Tomato has outgrown its ALU roots: 8‑bit, 32‑bit, even 40‑bit variants — a 3R1W 32,768 GPR register file and the VLIW architecture it somehow demands.

IV · Verification & Testing

10 billion on the byte. 130 billion on the word.

The dual-LUT ALU in hardware/fpga/core is the machine that runs Tomato OS. Verilator ran 10 billion vectors on the 8-bit slice and 130 billion on the full 32-bit ALU against a golden model — every mismatch aborts. SymbiYosys proved the same datapath at 1b, 8b, and 32b.
