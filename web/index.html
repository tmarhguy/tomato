01 / WHAT IS TOMATO?Processor · software · hardware

What is Tomato?

A 32-bit computer I designed from the processor up in my dorm, during sophomore year.

  • Dual-LUT3 ALU · 524,288 configurations — f(A,B,C) + g(A,B,C) + Cin in one cycle.
  • 52 mapped instructions — from 512 opcode slots; more still landing.
  • Three-source datapath — compound Boolean and arithmetic without intermediate steps.
  • 32,768 × 32-bit registers — banked file, three reads, one write.
  • 16-format immediate box — imm7/imm12-style widths for native ISA remaps.
  • Distributed control — local ROMs beside the units they drive.
  • Assembler + Tomato OS on FPGA — graphics, games, video, and input on my CPU.
  • RTL and discrete 74xx — same architecture in FPGA, KiCad, and copper.
  • 130 billion ALU test vectors — simulation and formal checks at 1, 8, and 32 bits.

Its logic can change with each instruction.

04 / WHAT MAKES IT DIFFERENTThe Dual-LUT arithmetic logic unit

One circuit.
524,288 ways to configure it.

The ALU is the processor’s arithmetic and logic engine. I gave mine two programmable truth tables per bit and wired them straight into an adder.

An instruction can change those tables. So the same circuit can add numbers, combine bits, or combine bits and add—all in one trip through the ALU.

For example, the same hardware can compute A + B or A + (B AND C). Change the truth tables, and the adder receives a different calculation.

For the engineer: what does 524,288 actually count?

Two independently programmed LUT3 planes offer 256 × 256 truth-table pairs. Eight carry-source selections give 524,288 control configurations. Some configurations produce the same function. The instruction ROM has 512 rows and selects a practical subset.

The datapath computes f(A,B,C) + g(A,B,C) + carry. One ALU evaluation is distinct from a complete CPU instruction or a whole-program speedup.

How one instruction configures the whole datapath

Why I call it polymorphic

One datapath.
Different logic with each instruction.

I use polymorphic to describe how an instruction configures the machine’s existing paths. It starts with the Dual-LUT ALU: two programmable Boolean functions feed the same adder. Change their truth tables and carry selection, and the circuit can perform ordinary arithmetic, logic, or a compound expression such as A + (B AND C).

The flexibility extends beyond the ALU. The instruction ROM also selects operand sources, immediate interpretation, and the controls for flags, write-back, and sequencing. The immediate box is one part of that system: it constructs a value from instruction bits combinationally, without a separate conversion instruction.

Both the operation and the way its operands reach it can change. That is the idea behind the name. ISA profiles map supported operations onto these controls; a profile alone does not establish compatibility with unmodified foreign binaries.

COUNTER FSMLatch a matching opcode

Hardware-level compilerFind the operation once.
Reuse it in one ALU pass.

A counter FSM that acts as a primitive hardware compiler. At about 1–10 MHz it brute-forces the ALU’s 65,536 Dual-LUT configurations in milliseconds.

You supply fixed inputs and a target output. The FSM sweeps opcode space, freezes on a match, and latches that opcode—so I can reuse exotic single-cycle operations that would otherwise take many instructions.

A match is still a candidate to verify—yes, but the search is nearly instant at intended frequencies.

05 / ROOM TO THINK32,768 × 32-BIT REGISTER FILE

Ordinary memory chips. Unusual scale.

Half the register
capacity of one
NVIDIA Blackwell SM.

32,768 register locations. Built into my own computer architecture.

Registers are a processor’s working storage: places to keep the numbers it is using right now. I gave Tomato room for 32,768 values, each 32 bits wide, by using the full 15-bit address depth of its AS6C62256 SRAM chips (32K × 8).

For perspective: RISC-V RV32I exposes 32 architectural integer registers, including x0, which is fixed at zero. One streaming multiprocessor (SM) inside an NVIDIA Blackwell GPU has 65,536 32-bit registers. Tomato sits between those worlds—banked storage on a homebrew CPU, not a GPU.

The AS6C62256 chips give me 15 address bits. I use all of them.

WHERE THE DATAPATH MAKES A DIFFERENCEBase RV32I vs Tomato Dual-LUT

If I can’t win on frequency,
I want to win on expressiveness.

A discrete machine may not chase GHz clocks—but it can pack more useful work into each cycle. Tomato’s Dual-LUT path turns compound Boolean and arithmetic into fewer ALU passes: more done per instruction, fewer steps for the same job. 06 / NUMBERS INSIDE INSTRUCTIONSThe immediate box · 16 decode choices

A small number.
Ready for a
32-bit machine.

To say “add 5,” I need a way to put the number 5 directly into an instruction. That embedded number is called an immediate.

I gave Tomato an immediate box with 16 decode choices. It can read short constants, preserve negative numbers, position upper bits, or scale a branch offset to a word address.

The result is always a 32-bit value the rest of the machine can use. A small instruction field becomes an operand, an address offset, or the upper part of a larger number.

07 / THE PARTS WORK TOGETHERFrom instruction to result

One instruction.
A path through the machine.

I built the CPU around a simple loop: read an instruction, set up the circuits, do the work, and store the result.

  1. 01 / FETCH

    Read the instruction

    The program counter points to the next 32-bit word in memory.

  2. 02 / DECODE

    Set the controls

    A 9-bit opcode selects a row from the 512-row instruction ROM.

  3. 03 / EXECUTE

    Do the calculation

    Three register read ports supply A, B, and C. The immediate box supplies constants when needed.

  4. 04 / WRITE BACK

    Keep the result

    The write port stores the answer. A branch can change which instruction comes next.

FAQSix answers · then the full page

Still wondering?

The questions people ask first—answered briefly here.

Why two LUTs instead of one?

A second LUT costs two extra packages per nibble, but gives the adder an independent Boolean plane. That is the trade for compound work like XOR, NAND, and arithmetic in one trip. More

Why three inputs—not two or four?

Two felt too close to a 74181. Four blows up the lookup hardware. Three keeps each truth table at eight entries while still fitting A + (B AND C) in one evaluation. More

What actually happens in the ALU?

Inputs feed two lookup planes; their outputs go straight into the adder: f(A,B,C) + g(A,B,C) + cin. There is no final mux choosing between separate logic and arithmetic results. More

Are there really 524,288 different operations?

256 × 256 × 8 carry sources = 524,288 control settings. Many implement the same function. That is control space—not 524,288 unique instructions in the ROM. More

What is the hardware compiler?

A counter FSM that brute-forces 65,536 Dual-LUT configs at about 1–10 MHz, freezes on a match, and latches that opcode for reuse. A match is still a candidate to verify. More

Has the entire CPU been formally verified?

Not yet. The ALU has simulation and formal checks. The whole CPU has Verilog simulation and software running on FPGA—different evidence. ALU proofs are not a proof of the complete computer. More
