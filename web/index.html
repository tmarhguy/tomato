The Predecessor

Before Tomato, there was the transistor board.

Same story, same narrative—but this time, it had to be smarter.

By Tyrone Marhguy · Computer Engineering ’28

Before Tomato, there was an 8‑bit ALU built from roughly 3,488 discrete CMOS transistors across a massive 270×270 mm board. It was a beast in its own right: capable of 19 operations, sporting 5 flags, and power hungry.

But for a solo dorm-room project, the manufacturing costs ballooned exponentially, so I needed a pivot. Same story, same narrative—but this time, it had to be smarter. Welcome to Tomato!

The Revolution

Tomato grew as an odd machine.

Tomato has grown into a 65k operational space (that’s a ~3,500× increase—the very reason Tomato wins). This leap comes from its dual‑LUT3 capacity, fused into an adder architecture that’s optimized for extreme linear scalability.

Core equation

out = adder(mux(An, Bn, Cn), mux(An, Bn, Cn), mux(carry / flags))

Operation family

f(a, b, c) + g(a, b, c) + h(cin)

By design, Tomato can resolve any Boolean operation of the family f(a, b, c) + g(a, b, c) + h(cin) in a single clock cycle. This isn’t just a party trick—it melts down complex, cycle-heavy algorithms into native hardware steps.

It opens the door for single-cycle Fused Mask-and-Add operations like A + (B AND C) for instant framebuffer manipulation, or native cryptographic acceleration: computing A + ((A AND B) XOR (NOT A AND C))—the core SHA-256 Choose function—in exactly one cycle.

II. The Hardware Compiler

Think compiler in hardware

In my most fancy test with a custom FSM, it is capable of sweeping to find the matching opcode—sweep counting till it matches an input A, B, C and expected value. So yes: it can compress (infinite) boolean local operations of its family to resolve a single opcode that solves it at the hardware level.

I took that FSM onto an Artix‑7. At the board’s set speed it crunched the space and found a match in 1 min 14 s. Watching it land was inspiring. Opcode compiler →

III. The Build Philosophy

74xx now. Transistors someday.

For now, Tomato is built exclusively from 74xx series logic chips—driven purely by manufacturability and brutal time constraints.(Someday, I will lay them out as raw transistors, just as I always intended. ) But even in its current form, Tomato has outgrown its ALU roots. It has taken on multiple shapes: 8‑bit, 32‑bit, even 40‑bit variants—it accommodates a quirky 3‑Read‑1‑Write 256 General Purpose Registers register file I designed for it and the very‑long‑word instruction (VLWI) architecture it somehow demands.

IV. Verification & Testing

The 130-billion vector gauntlet

Schematic eyeballing is not a tapeout. I exported the board into Verilog from Digital, then Verilator compiled it to C++ so brute-force benches were actually viable: 10 billion directed and random vectors on the ALU core, then 130 billion across the entire 32-bit slice. Simulation is still simulation. SymbiYosys k-induction proved the logic plane is an ALU—no untested edge. Last gauntlet: the architecture on FPGA, alive on the first toggle of the 4-bit sample. After more than 639 hours poured into a custom computer from absolute scratch, this is where we stand.

The first programs were hex I wrote by hand. Then an assembler cobbled together on the fly, FPGA tests on the Artix‑7, simulations that ran for days, and bugs hunted at 3 AM. Dual-LUT copper is inbound; the rest of the machine is still being laid.

Tomato is the little obsession, the evolved ALU, and the most rewarding migraine I’ve ever built.
