The instruction set

The words that drive the machine.

Tomato’s instructions select the logic, constants, and routes through its processor. Here is how I map a program onto those controls—and where the instruction coverage still needs work.

Polymorphism includes the operand format. The immediate box can sign-extend a 13-bit offset, zero-extend a 16-bit literal, or place a LUI field in the upper 20 bits. Decode selects these combinational paths without a separate conversion instruction or clock cycle. Instruction overlays and programmable ALU truth tables complete the mapping.

I program Tomato in its own assembly language. A 9-bit opcode selects a control word for the ALU truth tables, immediate format, writeback path, and branch controls. The assembler reads mapping tables and emits machine code for the FPGA memory or discrete hardware. ISA profiles describe how other operations can fit those controls; their implementation and test status must be checked individually.

How you use it

  1. Pick or add an opcode in tomato.v1.csv. A burn is a real ROM row. Empty rows stay nop.
  2. Spell it in assembly with software/assembler.py. Mnemonics come from the CSV, not hard-coded Python.
  3. Add syntax sugar in tomato.v1.pseudo.csv if you want CALL, BEQZ, or LI without growing the ROM.
  4. Assemble and burn. Tomato OS and test benches share the same flow: assemble tomato_os.s, load the image, run on Nexys or in simulation.
  5. Map another ISA when you need it — overlay bits, immediate box encoding, LUT pair — as rows in profiles/, not as new microcode.

Native Tomato syntax is opcode rd, rA, rB, rC where the ALU computes rd = f(a,b,c) + g(a,b,c) + cin. Everything else is convenience on top of burns.

What lands in the 32-bit word

Three mechanisms absorb most integer ISAs without a pre-decode stage:

  1. 01 · Overlay

    Low bits reuse

    The bottom three bits of the instruction overlay as COND, jump mode, or a short immediate fragment. Same silicon; different mnemonics.

    Word layout

  2. 02 · Immediate

    Literal box

    Sixteen immediate encodings on the register board — imm8 through imm16 and LUI — sized for the common RISC and CISC literal widths.

  3. 03 · ALU

    Dual-LUT plane

    Any op that fits f+g+cin runs in one cycle. The opcode loads the truth tables. Mapping a foreign ALU op is table entry, not a redesign.

Family maps (~37)

The profiles/ folder lists more rows than anyone would name at a bench — separate CSVs per RISC-V extension, ARM core, PIC variant. Count the families you would actually say out loud (RV32, MIPS, ARM, x86, 6502, Z80, …) and you land around thirty-seven. That number moves when a new map ships; it is not a spec limit. The hardware already accepts the encoding family. The work is writing the map.

What this does not cover

The mappings cover compute, shift, and register or memory operations that fit this datapath. Full binary compatibility also depends on instruction decoding, exceptions, memory behavior, and system features. A mapping file alone does not establish that compatibility. The profile tables record gaps and test status so the software work can address them.
