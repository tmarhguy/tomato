ISA as a Wire

Tomato is a parametric datapath, not an emulator. The instruction word is the configuration. About thirty-seven family maps so far — and counting.

Authority · docs/isa/tomato.v1.csv · the argument in the vault

A 512-row opcode ROM is enough for native ALU ops, load and store, branches, shifts, and mul/div without empty decode fanout. The 9-bit opcode does not trigger a microcode interpreter. It loads a control word that is the mux select. One cycle. Foreign binaries are maps onto that word — not a second machine in copper.

Solidified burns stay. New burns are added when a program needs them. The LUT catalog still knows more functions than the instruction ROM exposes—that was always the plan. Native syntax: opcode rd, rA, rB, rC where rd = f(a,b,c) + g(a,b,c) + cin.

How a foreign encoding lands

Three pieces of copper absorb the common integer ISAs without a pre-decode shift or a software layer in ROM.

Overlay word. Low bits of the 32-bit instruction dynamically overlay as COND, jump mode, or an immediate fragment. Same slices. Different assembly spellings.

Immediate box. Sixteen encodings on the register board — imm8, imm12, imm13, imm16, LUI — natively parse the literal styles of RISC-V, MIPS, ARM, and x86 without a cycle of packing logic in front of execute.

Dual-LUT ALU. Any operation that fits f(a,b,c) + g(a,b,c) + cin executes in one cycle: the opcode loads the LUTs with the truth table. An ISA is a parametric mapping from an external binary onto that family. Supporting a new one is a data-entry problem, not a microarchitecture redesign.

About thirty-seven, casually

Count every CSV in profiles/ and you get sixty-something — RISC-V extensions, ARM cores, SuperH revisions, PIC variants listed separately because the opcode compiler’s sweep database is a spreadsheet. Count the families a person would name at a bench and you land around thirty-seven. That integer is not a ceiling. The hardware accepts the family. More burns and tighter overlay packing move the casual count; optimization on Tomato changes it for the better. Why the number stopped being the headline →

What the word will not do

No tile VPU. Display is CPU-painted tile RAM with independent VGA scanout. Games stay software. A future rect blitter is optional — not a sprite engine hiding in the opcode space.

The maps cover the compute, shift, and register-access layers. Tomato does not claim x86 segmentation or ARM TrustZone — those are system-level constructs, not muxes on this datapath. For the bulk of integer code that is ALU, shifter, and load/store, execution is native. Mapped, not interpreted.
