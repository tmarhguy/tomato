== Introduction

This chapter states what the system is, what it is not, and how to read
the rest of the manual.
It uses the canonical vocabulary from `docs/status.md`.

=== Purpose and scope

The project is one 32-bit architecture expressed at several layers:

* a physically assembled 8-bit 74xx Dual-LUT ALU slice (proves the ALU
  construction, not a complete discrete computer);
* a complete FPGA machine on the Nexys A7-100T that boots the
  assembly-written operating system (the complete running computer);
* a functional browser ISA emulator (functional behavior only, not
  cycle-accurate RTL or physical execution);
* local RTL simulation driven by Icarus Verilog.

The complete discrete computer remains a goal.
Source presence alone never proves deployment, programming of a board,
or availability of an external bridge.

Section <<architecture>> defines the machine.
Section <<verification>> defines what has been checked and how to reproduce it.
Section <<limitations>> states explicit non-claims.

=== Conventions

Inline code such as `r0`, `SETBANK2`, or `0x780000` denotes register,
instruction, or address literals.
File paths such as `hardware/fpga/core/rtl/regs.v` are repository-relative.
Status words follow `docs/documentation-policy.md`:

* _Implemented_ — present in current source.
* _Verified_ — a named reproducible check passed against that source.
* _Hardware-demonstrated_ — direct evidence identifies the hardware shown.
* _Deployed_ — the artifact is confirmed at its public endpoint.
* _Preview_ — intentionally incomplete behavior.
* _Planned_ — no current implementation claim.

NOTE: Emulator screenshots, simulation logs, and generated bitstreams are
evidence of the target they ran on only.
Label every result with its execution target.
