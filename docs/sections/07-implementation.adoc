[[implementation]]
== Implementation

This chapter describes how the checked-in sources become a bitstream and
what the build does and does not prove.

=== Build flow

The default documented flow is Yosys -> nextpnr-xilinx -> Project X-Ray,
with an optional Linux Vivado batch target for the same board.
Neither target alone proves a currently programmed board.

[source,bash]
----
make fpga-setup
make fpga
----

Programming is intentionally a separate, hardware-changing action; see
`hardware/fpga/README.md`.
Implementation reports (timing, utilization) live under
`hardware/fpga/core/reports/` when generated.

=== Memory image and burns

ISA sources generate the images both the FPGA and the browser consume:

[source,bash]
----
python3 tools/gen_microcode_v1.py --pack-rom   # regenerate v1 + .mem
cd hardware/fpga/core && make burn              # embed into rtl/burn/
----

* Edit: Digital schematics, ISA CSVs, assembly sources, FPGA/browser sources.
* Regenerate: `.mem` images, `rtl/burn/*.vh`, browser firmware image,
  bitstreams. These are derived artifacts, not design authorities.
* Runtime state: FPGA RAM, registers, framebuffer, compiler and radio
  mailbox contents are volatile. Reset or reload restores the compiled image.

=== Physical and board scope

The physically assembled ALU slice proves the Dual-LUT construction on
74xx hardware; it is not a complete discrete machine.
The complete machine in this repository is the FPGA implementation on the
Nexys A7-100T.

Relevant source trees:

[width="100%",cols="30%,70%",options="header"]
|===
|Path |Purpose
|`hardware/digital/` |Editable architecture schematics
|`hardware/kicad/` |PCB designs and assembly records
|`hardware/fpga/` |Complete machine, board harness, and simulation
|`software/` |Assembler, programs, and operating system
|`microcode/` |Control-ROM packaging
|`verification/` |ALU and implementation checks
|`web/` |Project site and browser emulator (separate deployment)
|===

TIP: Board photographs identify hardware; a result requires an associated
run record or visibly grounded capture. Keep provenance in captions, alt
text, and metadata when images are copied.
